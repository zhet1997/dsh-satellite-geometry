这是工作流入口。真实建模规则按 DSH 会话固定为不可变版本，不通过覆盖全局文件切换。

1. 首先调用 `satellite_workflow_context`，取得当前工程、实际 Skill 正文及 SHA-256 指纹，并遵循该正文。未选工程时可传明确的 projectId；当前版本无法更换为另一个版本，要在新会话中绑定。
2. 消息中的 `SG-` 引用用 `satellite_selection_context` 读取固定对象与原修订；超过一页时分页读取。写前读取当前 revision。引用属于发送它的会话，不随新选择改变。
3. 资料原文用卫星文档工具读取。中文名称、热参数和约束应有依据，不知道则保留未知。
4. 用结构化 recipe 表达单机，支持盒体、圆柱＋底座、面壳；保持原布局。面壳为面集合，厚度/材料等另存，体积不是物理质量依据。
5. 工程师纠正直接重建当前方案。手动命名方案副本可保存/载入，不额外要求每一步接受。关联会话与意见只做记录，不实时修改 Skill。
6. 重建返回 jobId，查询完成后读取方案、测量和接触状态。真实源干涉与简化新增重叠分开；安装接触候选不能当热导通认证。
7. 输出简化 STEP、单机方案/属性和热接触清单。导出成功、几何检查通过和工程质量合格是不同结论。

能力通过卫星 MCP/API 提供；不要运行任意 Python 生成代码代替结构化方案。外部测试框架使用相同业务接口，评分由外部完成。
